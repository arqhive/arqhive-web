## 자세히

### 2026-10-10 · arqhive-web · 추가 다운로드 버튼이 안 그려지는데 운영 HTML grep으로 "반영됨" 보고
- 유형: 검사 도구 맹점
- 무슨 일: 파르테나(3DS)에 Azahar 폰트를 `extraDownloads`로 넣고, 운영 HTML에서 「Azahar 한글 폰트」·파일 이름이 나오는 걸 보고 버튼이 생겼다고 보고했다. 실제로는 `ReleaseHint`가 CIA·LayeredFS 갈래가 있으면 갈래 버튼만 그리고 끝나 `extraDownloads`를 그리지 않았다. 사용자가 화면 캡처로 알려 줌.
- 왜: ① grep에 걸린 글자가 어디서 왔는지 보지 않았다. 같은 문구가 mdx 본문과 RSC 데이터에도 있어 버튼이 없어도 걸린다. ② 넣기 전에 그 필드를 그리는 컴포넌트의 분기(갈래 있음/없음)를 읽지 않고, 환영이문록(갈래 없음)에서 됐으니 같다고 가정했다. ③ 화면을 열어 보지 않고 문자열 존재만으로 판정했다.
- 교훈: 화면 요소 반영은 문자열이 아니라 요소 자체로 확인한다(`<a … data-track="download-extra"` 같은 고유 속성으로 찾거나 브라우저로 열어 본다). 콘텐츠 필드를 새 조합(갈래 있는 패치 + 추가 다운로드)으로 쓸 때는 그 필드를 그리는 컴포넌트의 분기를 먼저 읽는다. 이번 경우는 E2E 검사로 막았다.

### 2026-10-07 · arqhive-web · 개발 서버를 TaskStop으로만 꺼서 프로세스가 쌓이고 포트가 밀림
- 유형: 경로/환경
- 무슨 일: API 개발 서버(wrangler dev)를 백그라운드 작업 중지(TaskStop)로 끄고 다시 띄웠더니, 8787을 옛 workerd가 계속 잡고 있어 새 서버가 8788로 떴다(웹은 8787을 봄). 확인해 보니 wrangler 트리(cmd→node→node→workerd 여럿)가 세 벌 남아 있었다. 그 전에도 웹 개발 서버가 시간 제한으로 "꺼졌다"고 떴지만 실제로는 살아 있어 3000을 잡고 있었다.
- 왜: TaskStop이 셸만 끝내고 Windows의 자식 프로세스 트리는 남긴다는 걸 몰랐다. 포트 하나만 보고 PID 하나를 끄면 부모 wrangler가 workerd를 다시 띄운다. "새로 띄우면 같은 포트에 뜬다"고 가정하고 Ready 줄의 포트를 확인하지 않았다.
- 교훈: Windows에서 개발 서버를 끌 때는 `Get-CimInstance Win32_Process`로 `wrangler|next dev` 트리를 찾아 **최상위 cmd PID에 `taskkill /T /F`**를 한다. 다시 띄운 뒤에는 로그의 `Ready on` 포트가 기대한 포트(8787·3000)인지 먼저 본다.

### 2026-10-07 · arqhive-web · 평가 결과 파일 이름 수정이 조용히 실패해 1차 결과를 덮어씀
- 유형: 검증 누락
- 무슨 일: 평가 결과 파일 이름에 지시문 버전을 넣으려고 파이썬 `str.replace`로 고쳤는데, Biome가 그 줄을 이미 여러 줄로 재정렬해 둔 뒤라 찾는 문자열이 없어 아무것도 안 바뀌었다(assert 없이 replace만 써서 실패를 몰랐다). 2차 평가가 같은 이름으로 저장돼 1차 결과 파일을 덮어씀. 콘솔 기록에서 요약·사례별 줄을 되살렸지만 사례별 실행 기록은 잃음.
- 왜: ① 바꿀 대상이 있는지 확인하지 않는 치환(`s.replace`)을 썼다 — 다른 치환들에는 assert를 넣으면서 이 줄만 빠뜨렸다. ② 포맷터가 파일을 바꾼 뒤 예전 모양을 기준으로 치환했다. ③ 결과 파일 이름이 날짜까지만이라 같은 날 두 번 돌리면 덮어쓰는 설계였다.
- 교훈: 스크립트 치환은 항상 "찾았는지" 확인(assert 또는 개수 출력)한다. 실험 결과처럼 다시 만들 수 없는 산출물은 **덮어쓰지 않는 이름**(시각 포함)으로 저장한다. 포맷터를 돌린 파일은 다시 읽고 고친다(Edit 도구 사용).

### 2026-10-03 · arqhive-web · Cloudflare Tunnel을 추천하면서 "도메인 필요" 전제를 빠뜨림
- 유형: 검증 누락(전제 조건)
- 무슨 일: 무료 주소(`*.vercel.app`)로 운영하기로 정한 뒤, VM 연결 방식으로 Cloudflare Tunnel을 "무료, 카드 불필요"라고 추천했고 사용자가 확정했다. 문서에 반영하려고 경로를 하나씩 적다가, Tunnel의 고정 공개 주소에는 Cloudflare에 등록된 도메인이 필요하다는 점을 그제서야 확인했다. 문서에 제약과 대안(Workers VPC, 도메인 구매, Tailscale Funnel)을 적고 사용자에게 알렸다.
- 왜: ① 기술을 비용(무료·카드) 기준으로만 걸렀다. "이미 정한 조건(도메인 없음)에서 동작하는가"는 따로 검사하지 않았다. ② Tunnel의 장점(들어오는 포트 없음)을 설명하는 데 집중해서, 그 장점이 성립하는 전제(도메인 zone)를 떠올리지 않았다. ③ 경로를 끝에서 끝까지(브라우저 → api → VM) 그려 보는 일이 문서화 단계에서야 일어났다.
- 교훈: 기술을 추천할 때는 비용과 함께 **이미 확정된 조건(무료 주소, 카드 여부, 언어 등)과 하나씩 대조**하고, 전제 조건(도메인, 리전, 검수 등)을 같은 문단에 적는다. 연결 방식을 제안할 때는 **요청이 실제로 지나가는 경로를 끝까지 적어 보고** 나서 추천한다.

### 2026-10-02 · 기프트피아 · 셸 heredoc 으로 파이썬 코드를 고치다 바이트 리터럴이 깨짐
- 유형: 도구 사용법
- 무슨 일: Bash heredoc 안의 파이썬이 다시 문자열(''' ''')로 코드를 써 넣는 2중 구조에서 `\\xff` 가 실제 문자 ÿ·널로 바뀌어 `tools/thp.py` 가 「null bytes」로 깨짐(스스로 발견, Write 로 파일 전체 다시 씀).
- 왜: 이스케이프가 셸·바깥 파이썬·안쪽 문자열 세 겹을 거치며 한 번 더 풀렸다. 바이트 리터럴이 든 코드를 문자열 치환으로 끼워 넣은 게 근본 원인.
- 교훈: `\x..` 같은 이스케이프가 든 코드는 Write/Edit 도구로 직접 쓴다(heredoc 속 문자열 치환 금지). 고친 뒤 `python -c "compile(...)"` 로 바로 확인.
- 재발(같은 날 7단계): `'\\n'` 이 든 줄을 heredoc 치환으로 넣다 실제 줄바꿈으로 풀려 구문 오류. 교훈을 기록하고도 「짧은 한 줄」이라 heredoc 을 또 씀 → 백슬래시가 한 글자라도 들면 무조건 Edit 도구.
- 재발(10/2 스타폭스 어드벤처, 다른 세션): 스킬 문서에 윈도 경로(`C:\\Users\\...`)가 든 문단을 heredoc 속 파이썬 문자열로 넣다 `\U` 이스케이프 오류(파일은 안 깨짐). 코드가 아니라 "문서 문장"이라 방심함 → 백슬래시가 든 글은 코드든 문서든 Edit 도구.
- 재발(같은 날, 같은 세션 두 번째): 검사용 한 줄짜리 파이썬(`b'\\Users\\'`)을 heredoc 에 넣어 구문 오류. 기록 직후인데도 "검사 코드 한 줄"이라 또 씀 → 검사 조건 자체를 백슬래시 없는 문자열(`b'AppData'`)로 바꾸는 게 가장 확실.
- 재발(10/7 arqhive-web): 새 파일(instrumentation.ts, 템플릿 문자열 속 `\n`·백틱)을 heredoc 파이썬의 `'''…'''`로 통째로 써서 이스케이프가 풀려 구문 오류. "새 파일 만들기"라 치환 규칙과 다르다고 여김 → **새 파일 내용에 백슬래시가 있으면 Write 도구**로 쓴다.
- 재발(10/7 같은 날 두 번째): 정규식(`\d`)과 경로 치환(`'\\'`)이 든 파이썬을 heredoc으로 보내 문법 오류(실행 전 멈춰 변경 없음). → 파이썬에 백슬래시가 한 글자라도 들면 **Write로 .py 파일을 만들어 실행**한다(heredoc 금지).
- 재발(10/7 arqhive 에이전트 v3): 여러 파일을 고치는 긴 파이썬(정규식 `\s`, `r"C:\…"` 경로)을 `cat > x.py <<'EOF'`로 써서 셸이 따옴표 짝을 못 찾고 멈춤(변경 없음). "heredoc으로 파일을 만드는 것"은 Write와 같다고 여김 → **.py 파일도 Write 도구로 만든다**. heredoc은 백슬래시 없는 짧은 커밋 메시지에만.
