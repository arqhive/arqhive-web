# 0005. 알림은 카카오톡 하나로 한다

- 상태: 채택
- 날짜: 2026-10-03

## 맥락

- 새 제보와 검토 대기 제보를 운영자가 바로 알아야 한다. 운영자 본인 이름으로 만든 이슈에는 GitHub 알림이 오지 않는다(0004).
- 관리자 화면이 없으므로 검토 대기 제보의 승인·거절도 알림에서 해야 한다.
- 운영자는 관리 요소가 늘어나는 것을 원하지 않는다.

## 결정

- 카카오톡 **"나에게 보내기"** API로 알림을 보낸다. 메시지에 [승인] [거절] [이슈 보기] 버튼을 단다. 승인·거절 링크는 서명이 붙은 일회용이다.
- 알림은 DB(`notifications`)에 먼저 기록한 뒤 보낸다. 실패하면 그대로 남겨 두고 다음 Cron에서 다시 보낸다.
- 카카오 토큰은 DB(`integration_tokens`)에 암호화해 저장하고, Cron이 만료 전에 갱신한다.
- 디스코드 등 **다른 알림 수단은 두지 않는다.**

## 검토한 대안

- **디스코드 웹훅**: 설정이 가장 단순하고 토큰 갱신도 없지만, 평소 쓰지 않는 앱을 따로 확인해야 한다.
- **카카오톡 + 실패 시 디스코드**: 알림이 끊길 위험은 줄지만 관리할 서비스가 하나 늘어난다.
- **카카오 알림톡**: 사업자용 유료 서비스다.

## 결과

- 평소 쓰는 카카오톡으로 알림과 승인을 처리한다. 카카오 API 연동은 국내 포트폴리오에서 어필 포인트가 된다.
- 카카오 디벨로퍼스 앱(카카오톡 메시지 전송 동의 항목, 웹 도메인 `arqhive.vercel.app` 등록)이 필요하다.
- 토큰 갱신을 Cron이 맡는다. 갱신용 토큰도 만료되므로(약 2개월로 알려짐, 구현 때 카카오 문서로 다시 확인), 끊기면 카카오 로그인을 한 번 다시 해야 한다.
- "나에게 보내기"가 갑자기 실패했다는 사례가 있어 재전송 장치를 둔다.
