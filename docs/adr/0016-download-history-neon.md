# 0016. 다운로드 수를 Neon(Postgres) + Drizzle에 날마다 쌓고, Umami 통계와 함께 디스코드로 일일 정산을 보낸다

- 상태: 채택(0012 "DB 보류"를 이 기능에 한해 다시 연다)
- 날짜: 2026-10-07

## 맥락

- 다운로드 수는 페이지를 그릴 때 GitHub에서 "지금 값"만 읽는다. 과거 값이 남지 않아 하루에 몇 번 받았는지, 새 버전 뒤에 늘었는지 알 수 없다.
- 방문 통계(0015)는 Umami 대시보드에 들어가야 보인다. 운영자가 매일 열어 보지 않는다.
- 처음엔 다운로드 추이 그래프를 사이트에 공개하려 했으나, 운영자가 보는 게 목적이라 **공개하지 않고** 운영자 디스코드(0014의 웹훅)로 하루 한 번 정리해 받기로 했다.
- 0012에서 "다운로드 수 추이가 필요해지면 DB를 다시 검토"라고 적었다. 날짜별 값을 쌓는 일이라 DB가 실제로 필요하다. 운영자는 실무에서 쓰는 Postgres·ORM도 배워 보고 싶어 한다.
- 콘텐츠(패치 정보)는 그대로 MDX 파일에 둔다(관리자 화면·로그인이 필요해지고, git 기록을 잃고, 릴리즈 흐름과 맞지 않음).

## 결정

- **Neon(서버리스 Postgres, 무료 플랜) + Drizzle ORM**, 표 하나 `download_snapshots`
  | 열 | 타입 | 뜻 |
  |---|---|---|
  | `slug` | text | 패치(콘텐츠 slug) |
  | `day` | date | 한국 날짜 |
  | `total` | integer | 그날 잰 누적 다운로드 수(화면과 같은 셈법: 릴리즈마다 가장 많이 받은 파일 하나를 더함) |
  | 기본 키 `(slug, day)` | | 같은 날 다시 재면 덮어쓴다(upsert) |
- **`packages/db`**: 스키마·클라이언트·마이그레이션(drizzle-kit). Workers에서는 Neon HTTP 드라이버를 쓴다.
- **일일 정산(Workers Cron, 한국 시간 23시 50분)**
  1. 공개 패치마다 GitHub 릴리즈를 읽어 오늘 값을 저장한다. 셈법 함수는 `packages/shared`로 옮겨 web(화면)과 api(정산)가 같이 쓴다.
  2. 어제·7일 전 값과 비교해 오늘 증가분·주간 증가분을 낸다.
  3. Umami에서 오늘 하루치를 읽는다: 방문자·페이지뷰·평균 체류·이탈, 이벤트별 횟수(case-open·download·changelog-open·report-sent/failed), 패치별 케이스 열기·다운로드 클릭, 유입 경로.
     - Umami Cloud의 공식 API(API 키)는 **유료 플랜**이라, 무료인 **공유 링크(Share URL)**가 쓰는 내부 방식으로 읽는다(공유 ID → 읽기 토큰 → `x-umami-share-token`·`x-umami-share-context: 1` 헤더). 공식 문서에 없어 바뀌면 깨질 수 있다(실패하면 그 부분만 "읽지 못함"으로 표시).
  4. 디스코드 임베드 하나로 보낸다. 실패하면 0014의 "못 보낸 알림" 목록에 쌓여 다음 정각에 다시 간다.
- **TanStack Query**(학습 목적, 실제로 쓰는 자리만): 업데이트 내역 불러오기를 `useQuery`, 제보 보내기를 `useMutation`으로 바꾼다. Provider는 쓰는 페이지(진열장·제보)에만 둔다.
- 비밀값: `DATABASE_URL`, `UMAMI_SHARE_URL`(공유 링크를 아는 사람은 대시보드를 볼 수 있어 비밀값으로 다룬다) — 개발은 `.dev.vars`(마이그레이션용 `packages/db/.env`), 배포는 `wrangler secret put`.

## 검토한 대안(무료로 쓸 수 있는 것)

| 선택지 | 좋은 점 | 나쁜 점 |
|---|---|---|
| **Neon + Drizzle** (채택) | 기록이 다 남아 주간·월간 비교, 나중에 그래프도 바로 가능. Postgres라 실무 SQL·도구를 그대로 배움. Vercel(web 서버)에서도 같은 DB를 읽을 수 있음 | 쉬다가 첫 요청이 느림(콜드 스타트). 외부 서비스·비밀값이 하나 늘어남 |
| **Cloudflare D1** | Workers에 바인딩으로 바로 붙어 가장 간단(비밀값·콜드 스타트 없음), Drizzle 지원 | SQLite라 Postgres 실무 경험과 결이 다름. web(Vercel)에서 직접 읽기 어려움 |
| **KV에 어제 값만** | 이미 쓰는 저장소, 추가 설정 없음 | 하루 변동만 보이고 기록이 남지 않음. DB 학습 목적에 맞지 않음 |

D1이 가장 간단하지만, 기록을 남기는 것과 "실무 Postgres·ORM 배우기"가 목적에 들어 있어 Neon을 고른다.

## 결과

- 오늘부터 날짜별 값이 쌓인다(과거 값은 GitHub가 주지 않음). 첫날 정산에는 증가분이 없고, 다음 날부터 나온다.
- Cron이 하루 빠지면 그날 값이 비고, 다음 날 증가분은 이틀치가 된다(메시지에 "어제 기록 없음"으로 표시).
- Umami 통계는 공유 링크에서 켠 화면(개요·이벤트)만 읽을 수 있다. 공유 링크 방식이 막히면 ① 우리 API로 이벤트를 직접 세거나 ② 방문 통계를 빼고 대시보드 링크만 보낸다.
- 다운로드 그래프는 공개하지 않는다. 기록은 남으니 필요해지면 언제든 만들 수 있다.
