# 0018. 케이스 보기·업데이트 내역 모달은 네이티브 `<dialog>`(showModal)로 만든다

- 상태: 채택
- 날짜: 2026-10-07(결정은 2026-10-03 케이스 열기 시제품 때, 기록을 나중에 남김)

## 맥락

- 진열장에서 등줄기·표지·목록 줄을 누르면 케이스가 **그 자리에서 날아와(FLIP) 커지고, 3D로 회전하며 열린다**(0008). 열린 케이스 위에서 "업데이트 내역"을 누르면 그 위에 창이 하나 더 뜬다.
- 모달이라면 기본으로 필요한 것: 포커스를 모달 안에 가두기, 뒤 페이지를 조작 못 하게 하기, ESC로 닫기, 배경 어둡게, 화면 낭독기에 "모달 대화상자"로 알리기, 닫으면 누른 곳으로 포커스 되돌리기.
- 연출 쪽 사정: 무대에 `transform`(3D 회전)·`overflow`가 겹쳐 있다. 일반 요소로 띄우면 부모의 `transform`이 `position: fixed`의 기준을 바꾸고 z-index 싸움이 생긴다. FLIP은 "화면 기준 좌표"로 계산해야 단순하다.
- 운영비 0원(0002)·의존성은 꼭 필요할 때만, Biome 엄격 규칙(0007, 접근성 규칙 포함)을 지킨다.

## 결정

- 케이스 보기(`widgets/case-viewer`)와 업데이트 내역 창은 **HTML `<dialog>` + `showModal()`**로 만든다. 라이브러리를 쓰지 않는다.
- 브라우저가 주는 것을 그대로 쓴다: 포커스 가두기·뒤 페이지 inert, ESC(`cancel` 이벤트), `::backdrop`, 접근성 역할, **top layer**(부모의 `transform`·`overflow`·z-index와 무관하게 화면 기준으로 뜸).
- 브라우저가 주지 않는 것은 직접 메운다(`model/use-case-dialog.ts`).
  - **닫는 연출**: ESC는 브라우저가 연출 없이 바로 닫으므로 `cancel`을 막고(`preventDefault`) 연출이 있는 닫기로 바꾼다. 연출이 끝난 뒤(`transitionsSettled`) `close()`한다.
  - **배경 클릭으로 닫기**: 기본 기능이 아니다. 무대는 클릭을 통과시키고(`pointer-events-none`, 케이스만 받음) 클릭 대상이 dialog 자신일 때만 닫는다.
  - **겹친 dialog**: 안쪽(업데이트 내역)의 `cancel`이 React 트리를 타고 바깥으로 올라오므로 `event.target === event.currentTarget`일 때만 바깥을 닫는다. 업데이트 내역 창은 회전하는 무대 **바깥**에 둔다(top layer라 위치는 화면 기준).
  - **스크롤 잠금**: `showModal()`은 뒤 페이지 스크롤을 막지 않는다. JS 없이 CSS `html:has(dialog[open])`로 열려 있는 동안 문서 스크롤을 잠그고, 스크롤바 자리를 늘 비워 둬(`scrollbar-gutter: stable` + `overflow-y: scroll`) 잠글 때 화면이 옆으로 밀리지 않게 한다(10/5, `app/styles/globals.css`).
  - **주소와 상태 맞추기**: 열면 패치 주소, 닫으면 진열장 주소(`replaceState`). 브라우저가 직접 닫았을 때(`close` 이벤트)도 상태를 맞춘다.
- "동작 줄이기"(`prefers-reduced-motion`)면 연출 없이 바로 열고 닫는다.

## 검토한 대안(무료로 쓸 수 있는 것)

| 선택지 | 좋은 점 | 나쁜 점 |
|---|---|---|
| **네이티브 `<dialog>`** (채택) | 모달 기본기를 브라우저가 줌, top layer라 3D 무대·FLIP과 충돌 없음, 의존성 0, 포털 불필요 | 닫는 연출·배경 클릭·스크롤 잠금·겹친 dialog 처리는 직접 |
| Radix UI Dialog | 접근성·포커스·스크롤 잠금까지 검증된 구현, 문서 풍부 | 의존성 추가, 포털로 렌더링, 열고 닫는 연출을 라이브러리 상태 흐름에 맞춰야 함(FLIP·3D 단계와 이중 관리) |
| React Aria(Adobe) `useDialog`·`useModalOverlay` | 접근성 최상급, 훅이라 모양은 자유 | 의존성이 크고 배울 API가 많음, 결국 오버레이·포털 관리 필요 |
| Headless UI Dialog | 가벼움, Tailwind와 잘 맞음 | 전환(Transition) 방식이 자체 규칙이라 단계별 연출과 겹침, 의존성 추가 |
| `div` + 직접 구현 | 완전한 자유 | 포커스 가두기·inert·ESC·접근성 역할·z-index를 모두 손으로, 빠뜨리기 쉬움 |

어느 라이브러리를 써도 3D 무대·FLIP 연출 때문에 열고 닫는 순서는 직접 관리해야 한다. 그래서 "기본기는 브라우저, 연출만 직접"이 코드도 의존성도 가장 적다.

## 결과

- 포커스·ESC·접근성 역할을 따로 시험하지 않아도 브라우저 기본 동작으로 맞는다. 의존성이 늘지 않는다.
- 3D 회전 무대 안에서도 모달 위치가 틀어지지 않고, 업데이트 내역 창을 케이스 위에 겹쳐 띄울 수 있다.
- 대신 닫는 연출·배경 클릭·스크롤 잠금·겹친 dialog의 이벤트 전파를 직접 다룬다. 실제로 ESC로 닫을 때 상태가 어긋난 일이 있었다(10/6, 실수목록 "작품 주소로 연 케이스를 ESC로 닫으면 상태가 어긋남") — 브라우저가 스스로 닫는 경로(`close` 이벤트)까지 상태를 맞추는 것으로 고쳤다.
- `showModal()`은 Chrome 37·Firefox 98·Safari 15.4부터, 스크롤 잠금에 쓰는 `:has()`는 Chrome 105·Firefox 121·Safari 15.4부터 지원한다. 지원 브라우저 목록(browserslist)을 따로 정하지 않았으므로, 옛 브라우저를 지원해야 하면 이 결정을 다시 본다(그때도 `:has()` 대신 JS 스크롤 잠금으로 바꾸면 된다).
