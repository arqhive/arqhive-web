# 0013. 패치 상세는 케이스 속지가 맡고, 가이드·제보는 한 페이지씩 둔다

- 상태: 채택(기획 문서 5장 페이지 구성을 바꿈)
- 날짜: 2026-10-06

## 맥락

- 기획 문서 5장은 `/korean-translation/[slug]` 상세 페이지, `/guides`·`/guides/[slug]`, `/reports`·`/reports/new`·`/reports/[id]`를 따로 두었다.
- 진열장(0008)에서 케이스를 꺼내 열면 속지에 패치 정보가 보이는 연출이 사이트의 중심이 되었다.

## 결정

- **패치 상세는 케이스 속지가 맡는다.** 속지에 상태·버전·원본·방식·구동 확인·번역 범위·알려진 문제·다운로드 수, "업데이트 내역 보기"(CHANGELOG 모달)를 둔다. 매체(디스크·카트리지)를 누르면 최신 릴리즈 페이지로 간다.
- `/korean-translation/[slug]`는 별도 상세 화면이 아니라, 진열장을 그리고 그 작품의 케이스를 바로 여는 주소다(공유·검색용).
- 가이드는 `/guide` 한 페이지(버전 가이드·파이프라인 안내·자주 묻는 질문 아코디언, 패치 방식별 적용 방법 포함).
- 제보는 `/report` 한 페이지(양식 + 들어온 제보 목록). 제보 상세는 GitHub 이슈 링크로 대신한다.

## 검토한 대안

- **기획대로 상세·가이드 상세·제보 상세 페이지 분리**: 페이지 수가 늘고, 케이스 연출과 같은 정보를 두 번 보여 준다.

## 결과

- 사용자 동선이 진열장 하나로 모인다.
- **검색 노출이 약하다**: 속지는 케이스를 열 때 브라우저에서 그려져서, 작품 주소 페이지의 HTML 본문에 패치 정보가 없다. 검색 노출 작업에서 서버가 그린 본문을 넣어 보완해야 한다.
- 전후 비교 슬라이더, 필요한 원본(MD5) 표 등 상세 페이지용으로 계획한 내용은 아직 없다.
