# 0012. DB(Neon·Drizzle)는 보류하고 GitHub API·KV로 운영한다

- 상태: 채택(기획 문서 8장 2단계 "Neon + Drizzle"을 보류)
- 날짜: 2026-10-06

## 맥락

- 기획 단계에서는 2단계에 Neon(Postgres)+Drizzle을 넣어 릴리즈·다운로드 수 동기화, 제보 사본, 알림 재전송, 검색을 맡길 계획이었다.
- 실제로 만들어 보니 지금 필요한 일은 DB 없이 풀렸다.
  - 작품 정보: MDX 콘텐츠(Velite)
  - 다운로드 수·업데이트 내역: 페이지를 그릴 때 GitHub API를 부르고 Next.js 캐시(1시간)
  - 제보 목록·상태: GitHub 검색 API(5분 캐시)
  - 요청 제한·저장 용량: Workers KV
- 운영비 0원·관리 요소 최소화(0002)가 우선이다.

## 결정

- **Neon·Drizzle은 지금 넣지 않는다(보류).** `packages/db`도 만들지 않는다.
- 작은 상태값은 KV, 원본 데이터는 GitHub(릴리즈·이슈)와 콘텐츠 파일을 그대로 쓴다.
- 아래처럼 DB가 자연스럽게 필요한 기능이 생기면 그때 다시 검토한다.
  - 다운로드 수 **추이**(매일 기록해 그래프로): Workers Cron + DB
  - 제보 사본 + 제보 상세 페이지·전문 검색
  - 제보가 많아져 GitHub 검색 API 한도가 걱정될 때

## 검토한 대안

- **계획대로 Neon 도입**: 나중 기능에 미리 대비할 수 있지만, 지금은 쓸 데가 없는 DB를 동기화·마이그레이션까지 관리해야 한다.
- **Cloudflare D1**: Workers와 붙기 쉽지만 같은 이유로 지금은 필요 없다.

## 결과

- 관리할 것이 줄고 운영비가 0원으로 유지된다.
- 데이터의 출처가 하나(GitHub·콘텐츠)라 동기화 어긋남이 없다.
- 과거 값(다운로드 수 변화 등)은 남지 않는다.
- 페이지 캐시가 GitHub 호출을 막아 주므로, 방문자가 늘어도 GitHub 호출은 늘지 않는다.
