# 0019. 방문 통계를 GoatCounter로 옮기고, 이벤트 값은 이벤트 이름에 넣는다

- 상태: 채택(0015를 대체)
- 날짜: 2026-10-10

## 맥락

- 0015에서 Umami Cloud(무료 Hobby)를 골랐다. 공개 4일(10/6~10/9) 만에 월 10만 이벤트 한도에 닿아 **10월 남은 기간 수집이 멈췄다**. 이벤트에 붙은 값(path·seconds 등)까지 한도에 세는 것으로 보인다.
- 한도를 피하려고 체류 시간·스크롤 깊이·웹 바이탈·일반 클릭을 뺐지만(0015 「바뀐 점」), 이 값들은 어디서 머물고 무엇을 누르는지 보려고 넣은 것이라 아쉽다.
- 일일 정산(0016)은 Umami 공식 API가 유료라 공유 링크의 내부 방식으로 읽고 있었다. 문서에 없는 방식이라 Umami가 바꾸면 깨진다.
- 조건(0015와 같음): 운영비 0원(0002), 쿠키·동의 배너 없음, 스크립트가 가벼울 것, 이벤트를 셀 수 있을 것.

## 결정

- **GoatCounter(goatcounter.com 호스팅)**로 옮긴다. 공식 사이트 기준 "합리적인 공개 사용은 무료"이고 월 몇 회 같은 숫자 한도가 없다(하루 수백만 뷰 같은 사용만 막는다, 2026-10-10 확인).
- 줄였던 측정을 되살린다: 페이지뷰(주소가 바뀔 때마다), 모든 클릭(이름 붙인 행동·바깥 링크·그 밖의 링크와 단추), 페이지별 체류 시간, 스크롤 깊이, 웹 바이탈.
- GoatCounter 이벤트는 **이름 하나만** 받는다. 값은 이름 뒤에 빗금으로 잇는다(`case-open/star-fox-2`, `download/star-fox-2/파일`). 숫자는 담을 수 없어 구간으로 바꾼다(체류 `page-time/1-3m/guide`, 웹 바이탈은 등급 `web-vitals/LCP/good`). 이 규칙은 `@arqhive/shared`의 `eventPath`·`parseEventPath`·`TIME_BUCKETS`에 두고 web(보내기)과 api(정산)가 같이 쓴다.
- 운영 주소(`arqhive.vercel.app`)에서만 스크립트를 불러온다. 로컬·미리보기 배포는 세지 않는다. 스크립트의 자동 세기는 끄고(`no_onload`) 페이지뷰를 직접 센다(주소가 history API로 바뀌는 앱이라).
- 일일 정산은 **공식 API**(Bearer 키)로 읽는다. 키는 "Read statistics" 권한만, arqhive 사이트만 열어 둔다(`GOATCOUNTER_API_KEY`).

## 검토한 대안

무료로 쓸 수 있는 것만 비교한다(0002). 유료 플랜이 필요한 도구는 처음부터 뺐다.

| 도구 | 좋은 점 | 나쁜 점 | 우리 조건에서 |
|---|---|---|---|
| **GoatCounter** (채택) | 숫자 한도 없음. 쿠키 없음. 스크립트 약 3.5KB. 공식 API가 무료(초당 4회). 오픈소스라 직접 운영으로 옮길 수 있음 | 이벤트에 값을 못 붙임(이름에 넣어야 함). 머문 시간·이탈률이 없음. 대시보드가 소박함 | 값은 이름에 넣고 체류는 직접 재서 해결 |
| **Umami Cloud Hobby** (지금) | 대시보드가 좋고 이벤트 값을 붙일 수 있음 | 월 10만 한도(값도 셈). 공식 API는 유료라 정산이 공유 링크 우회에 기댐 | 한도 때문에 측정을 줄여야 함 |
| **Umami 직접 운영** | 한도 없음, 지금 코드 거의 그대로 | Node 서버와 DB를 따로 띄우고 지켜야 함(무료 호스팅으로는 잠들거나 한도가 있음) | 운영 부담이 이 사이트 규모에 비해 큼 |
| **Cloudflare Web Analytics** | 무료, 한도 없음, 쿠키 없음 | 페이지뷰만, 커스텀 이벤트 없음 | 패치별 행동을 못 셈 |
| **PostHog** | 무료 한도가 큼(월 100만 이벤트 수준), 이벤트 값·퍼널 | 스크립트가 무겁고 기능이 과함, 세션 녹화 등 개인정보 부담 | 이 사이트엔 과함 |

## 결과

- 측정을 줄이지 않고 다 센다. 공개 직후처럼 방문이 몰려도 수집이 멈추지 않는다.
- 정산이 공식 API를 쓰게 되어 공유 링크 우회(UMAMI_SHARE_URL)가 없어졌다.
- GoatCounter의 `count`는 **방문**(같은 사람이 8시간 안에 다시 하면 한 번)이다. 페이지뷰·이벤트 모두 그렇다. 정산 숫자를 Umami 시절과 바로 비교하지 않는다.
- 머문 시간은 GoatCounter가 재지 않아, 웹이 보이는 동안의 시간을 재서 구간 이벤트로 보낸다(정산의 「체류」 줄).
- 이벤트 이름 규칙(구간 이름 포함)을 바꾸면 지난 기록과 이어지지 않는다. 바꿀 때는 정산 코드와 함께 바꾼다.
- 10월 1~9일 Umami 기록은 Umami에만 있다(옮기지 않음).
