# 0004. 회원 기능 없이 제보를 GitHub 이슈로 받는다

- 상태: 채택(일부 대체: 검토 대기 → 0010, 처음엔 이미지 링크만 → 0011)
- 날짜: 2026-10-03

## 맥락

- 패치 이용자에게 오역·글자 깨짐·멈춤 같은 제보를 받고 싶다.
- 처음에는 소셜 로그인(카카오·네이버·GitHub)을, 다음에는 이메일·비밀번호·닉네임 가입과 메일 인증을 검토했다.
- 다른 한글패치 제작자 사이트는 대부분 회원 기능이 없다.
- 운영비 0원, 관리 요소 최소화가 우선이다(0002).

## 결정

- **회원 기능을 넣지 않는다.** 가입·로그인·관리자 화면이 없다.
- 제보는 사이트에서 **로그인 없이** 받는다. 받는 정보는 작품·버전·유형·환경·위치·내용·스크린샷 링크·닉네임(선택)뿐이다.
- 서버가 GitHub **fine-grained 개인 토큰**으로 해당 패치 저장소에 **운영자 본인 이름으로 이슈를 만든다.** 이슈 본문에 "사이트 제보" 표시와 양식을 넣고 `제보`·유형 라벨을 붙인다.
- 제보 처리(라벨, 닫기, 릴리즈 연결)는 GitHub에서 한다. 사이트는 이슈를 읽어 상태를 보여 준다.
- 스팸 대책: Turnstile → 요청 제한 → 길이·링크 수 제한 → Workers AI 판별. 의심되면 바로 올리지 않고 검토 대기로 두고, 카카오톡으로 서명된 일회용 "승인/거절" 링크를 보낸다(0005). AI 판별을 붙이기 전(4단계)에는 모든 제보를 검토 대기로 받는다.

## 검토한 대안

- **소셜 로그인**: 앱 등록과 검수(네이버)가 필요하고, 계정 관리 부담에 비해 얻는 게 적다.
- **이메일 가입 + 메일 인증**
  - 메일 발송에 **내 도메인이 필요**하다. Resend 무료도 보내는 도메인을 인증해야 하고, Cloudflare Email 발송은 유료 플랜에서만 된다.
  - Workers 무료 플랜의 CPU 10ms로는 **비밀번호 해시(scrypt)가 버겁다.** 해시를 약하게 할 수는 없으니 로그인 처리만 Vercel로 나눠야 했다.
  - 비용(도메인)과 관리 부담이 생겨서 뺐다.
- **GitHub 이슈 작성 화면으로 바로 보내기**: 가장 단순하지만 제보자에게 GitHub 계정이 필요하다.
- **사이트 DB에만 제보 저장**: 상태를 바꾸는 관리자 화면에 결국 로그인이 필요하다.
- **GitHub App으로 이슈 생성**: 작성자가 `앱이름[bot]`으로 표시된다. 운영자 이름으로 올리고 싶어서 개인 토큰을 쓴다.

## 결과

- 개인정보를 받지 않고, 계정·세션·비밀번호를 관리하지 않는다.
- 제보가 수정 작업을 하는 저장소에 바로 쌓인다.
- 스팸·욕설이 운영자 이름으로 공개될 수 있어서 여러 겹의 거르기와 검토 대기가 필요하다.
- 운영자 본인이 만든 이슈에는 GitHub 알림이 오지 않으므로 알림을 따로 둔다(0005).
- 제보자는 제보를 나중에 고치거나 지울 수 없다. 추가 정보는 이슈 댓글로 안내한다(GitHub 계정이 있는 사람만).
- 토큰은 Workers 비밀값으로만 두고, 권한은 선택한 공개 패치 저장소의 이슈 읽기·쓰기로 한정한다.
