# 0011. 제보 스크린샷은 R2에 올리고, 누적 9GB에서 막는다

- 상태: 채택(0004의 "처음에는 이미지 링크만" 부분을 대체)
- 날짜: 2026-10-06

## 맥락

- 오역·깨진 글자 제보는 스크린샷이 있어야 빨리 찾을 수 있다. 0004는 악용·과금 위험 때문에 처음엔 이미지 링크만 받기로 했다.
- GitHub API로는 이슈에 파일을 바로 올릴 수 없다.
- Cloudflare R2는 저장 10GB/월·쓰기 100만·읽기 1,000만 건까지 무료이고, 넘으면 자동 청구된다. R2에는 "여기서 멈춤" 같은 사용 한도 설정이 없다.

## 결정

- 스크린샷은 최대 3장, png·jpg·webp, **장당 5MB**까지 받는다. 브라우저가 올리기 전에 webp로 다시 저장해 위치 정보(EXIF)를 지운다. 서버는 파일 앞부분(매직 바이트)으로 진짜 이미지인지 확인한다.
- 버킷 `arqhive-reports`에 올리고, 이슈 본문에는 공개 주소(r2.dev) 링크를 넣는다.
- 올린 크기를 KV에 누적해(`storage:bytes`), **9GB**를 넘을 것 같으면 스크린샷은 빼고 **글만** 이슈로 만든다. 양식은 "저장 공간이 다 차서 스크린샷 없이 글만 등록되었습니다"라고 알린다. 10GB가 아니라 9GB인 이유는 KV가 천천히 퍼져 동시 요청 몇 건이 기준을 살짝 넘길 수 있어서다.

## 검토한 대안

- **이미지 링크만 받기**: 제보자가 이미지를 따로 올릴 곳을 찾아야 해 제보가 줄어든다.
- **장당 1MB로 줄이기**: 과금 위험은 더 줄지만, 사용자가 5MB를 원했다. 누적 한도로 과금은 막힌다.
- **넘으면 제보 전체 거절**: 글만이라도 받는 편이 낫다.

## 결과

- 무료 한도 안에서 스크린샷을 받는다. 최악(매일 하루 한도 50건×3장×5MB)이어도 9GB에서 멈춘다.
- 누적 숫자는 "올린 양"이라 R2에서 지워도 저절로 줄지 않는다. 정리 기능을 만들면 지운 만큼 빼야 한다(`releaseStorage`).
- r2.dev 주소는 Cloudflare가 개발용이라고 하는 주소(요청 수 제한)다. 도메인을 사면 버킷에 사용자 지정 도메인을 붙인다.
