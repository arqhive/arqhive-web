# 0003. 모노레포를 템플릿 없이 직접 구성한다

- 상태: 채택
- 날짜: 2026-10-03

## 맥락

- web(Next.js, Vercel)과 api(Hono, Workers)가 서로 다른 곳에 배포되지만, 같은 Zod 스키마와 타입을 써야 한다.
- 만드는 사람은 프론트엔드 경력이 길고 백엔드·인프라는 익숙하지 않다. 모든 파일의 이유를 스스로 설명할 수 있어야 한다.

## 결정

- **모노레포**: `apps/web`, `apps/api`, `packages/*`
- **도구**: pnpm 10 + Turborepo
- **공용 패키지는 빌드 없는 내부 패키지**로 둔다. TS 원본을 그대로 내보내고, 쓰는 쪽(Next.js, wrangler)이 함께 빌드한다.
- **시작 템플릿 없이 직접 구성**한다.
- 버전은 설치할 때의 최신 안정판을 쓰되, 호환 문제가 있는 것은 고정한다.
  - TypeScript는 **6.0**: 7.0은 새 네이티브 컴파일러라 기존 TS API가 빠져 있어서, Next.js 등 도구 호환을 확인한 뒤 올린다.
  - Vitest는 **4.1**: `@cloudflare/vitest-pool-workers`가 아직 Vitest 4만 지원한다.
  - pnpm은 **10**: 이미 검증된 판이고 Vercel 빌드와의 호환이 확실하다.
- 아직 쓰는 코드가 없는 패키지(`db`, `content`, `ui`)는 빈 껍데기를 만들지 않고, README로 역할과 만들 단계만 적어 둔다.

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| 단일 Next.js 앱 | Workers 쪽(큐, Cron, AI)을 넣을 자리가 없고 경계가 흐려진다 |
| 저장소 분리 | 공용 스키마를 npm 배포하거나 복사해야 해서 버전이 어긋나기 쉽다 |
| Nx | 기능은 많지만 이 규모에는 과하고 배울 게 많다 |
| Bun workspaces | Vercel·Workers 빌드 환경과 어긋날 수 있다 |
| 빌드된 패키지 | npm에 배포할 패키지가 없어 빌드 단계만 늘어난다 |
| create-t3-app, create-t3-turbo | tRPC·인증·모바일 앱 등 계획에 없는 것이 많다 |
| Better-T-Stack | 원하는 조합에 가깝지만, 생성된 코드를 다 이해하고 시작해야 하고 Workers 큐·Cron은 어차피 직접 구성해야 한다 |

## 결과

- PR 하나로 web·api·스키마를 함께 바꿀 수 있다.
- 처음 설정에 시간이 더 들지만, 모든 파일의 이유를 설명할 수 있다.
- 고정한 버전(TS 6, Vitest 4)은 Renovate 설정에 막아 두고, 호환이 확인되면 새 ADR과 함께 올린다.
