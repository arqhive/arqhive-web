# 0015. 방문 통계는 Umami Cloud로 하고, 이름 붙인 행동만 이벤트로 보낸다

- 상태: 채택
- 날짜: 2026-10-06(2026-10-09 측정 범위 줄임, 아래 「바뀐 점」)

## 맥락

- 어떤 패치를 많이 보고 받는지, 사람들이 어디서 들어와 어디서 떠나는지, 실제 방문자 기기에서 사이트가 얼마나 빠른지 알고 싶다.
- 조건
  - 운영비 0원(0002), 작은 개인 사이트
  - 방금 성능 작업을 했다(진열장 JS 276KB → 188KB, 화면 차단 CSS 28KB → 13.5KB). 통계 때문에 다시 무거워지면 안 된다.
  - 동의 배너(쿠키 팝업)를 띄우고 싶지 않다.
  - 방문자 다수가 게임·개조 쪽이라 광고 차단기 사용 비율이 높다고 본다.
  - 커스텀 이벤트가 필요하다(케이스 열기·다운로드·제보 결과 등).
- 기획 단계(project-plan)에서 Umami Cloud 계정을 만들어 두었다. 이 ADR은 그 선택을 다른 도구와 비교해 기록한다.

## 결정

- **Umami Cloud(무료 Hobby 플랜)**를 쓴다. 스크립트는 화면이 뜬 뒤 받고(afterInteractive), `data-domains`로 배포 주소에서만 수집한다.
- 사이트 전체 자동 측정(`apps/web/src/app/analytics`)
  - 이름 붙인 클릭만(document 하나에 이벤트 위임, HTML의 `data-track`): `case-open`·`download`·`download-extra`·`changelog-open`·`release-notes`
  - 페이지뷰·머문 시간·유입 경로는 Umami 스크립트가 스스로 센다.
  - 제보 결과(`report-sent`·`report-failed`, 패치·스크린샷 수·실패 이유만)
- 사용자가 입력한 글은 이벤트에 넣지 않는다.
- CSP에 스크립트 주소(`cloud.umami.is`)와 수집 주소(`gateway.umami.is`)를 둔다.

## 검토한 대안

무료로 쓸 수 있는 것만 비교한다(운영비 0원, 0002). 유료 플랜이 필요한 도구(Plausible 클라우드 등)는 처음부터 뺐다.

| 도구 | 좋은 점 | 나쁜 점 | 우리 조건에서 |
|---|---|---|---|
| **Umami Cloud** (채택) | 쿠키 없음 → 동의 배너 불필요. 스크립트 약 2KB. 커스텀 이벤트·이벤트 값 지원. 대시보드가 한 화면. 오픈소스라 나중에 직접 호스팅으로 옮길 수 있음 | 무료 플랜은 월 10만 이벤트, 보관 기간 제한. 클릭까지 다 세면 방문이 많아질 때 한도에 닿을 수 있음. 퍼널·코호트 같은 깊은 분석은 약함 | 지금 규모에 충분. 한도에 닿으면 클릭 측정을 줄이거나 직접 호스팅 |
| **Google Analytics 4 (gtag)** | 무료, 사실상 한도 없음. Search Console·광고와 연동. 퍼널·코호트·사용자 경로 등 기능이 가장 많음 | 쿠키 사용 → 원칙상 동의 배너·개인정보 처리방침 필요. 스크립트가 무겁다(수십 KB). 광고 차단기가 거의 다 막아 숫자가 적게 나옴. 원하는 보고서를 직접 만들어야 하는 경우가 많음. 데이터가 구글 광고 생태계와 연결 | 성능·배너·차단 문제 셋 다 걸림 |
| **Vercel Web Analytics** | 이미 Vercel에 배포 중이라 설정이 가장 쉬움. 쿠키 없음. Speed Insights(웹 바이탈)와 함께 씀 | Hobby 플랜은 월 5만 이벤트, **커스텀 이벤트는 Pro(유료)부터**. 한도를 넘으면 수집이 멈춤. 다른 호스팅으로 옮기면 못 씀 | 커스텀 이벤트가 필요해 탈락 |
| **Cloudflare Web Analytics** | 무료, 양 제한 없음, 쿠키 없음. API(Workers)가 이미 Cloudflare | **페이지뷰만**. 커스텀 이벤트·목표·퍼널 없음 | 패치별 행동을 못 셈 |
| **PostHog** | 무료 한도가 큼(월 100만 이벤트 수준). 이벤트 분석·퍼널·세션 녹화·기능 플래그까지 | 스크립트가 무겁고 기능이 과함. 세션 녹화는 개인정보 부담. 설정·학습 비용 큼 | 이 사이트 규모엔 과함 |

## 결과

- 동의 배너 없이 패치별 인기(케이스 열기·다운로드), 머문 시간, 유입 경로를 볼 수 있다.
- 통계 스크립트가 첫 화면을 막지 않는다(뒤에서 받음, 약 2KB).
- 월 10만 이벤트를 넘으면 그달 남은 기간은 수집이 멈춘다(2026-10-09 실제로 닿음, 아래).
- 광고 차단기를 쓰는 방문자는 Umami도 막을 수 있어, 숫자는 "최소치"로 읽는다.
- 로컬에서는 수집하지 않아 실제 전송은 배포에서만 확인된다(수집 주소를 잘못 적어 한 번 막혔던 일이 있음, 배포 직후 콘솔·네트워크로 확인할 것).

## 바뀐 점(2026-10-09)

- 공개 4일(10/6~10/9) 만에 Hobby 한도(월 10만)에 닿아 10월 남은 기간 수집이 멈췄다.
- 그동안 기록은 페이지뷰 6.5천, 이벤트 2.7만(체류 시간 8.1천·웹 바이탈 6.2천·스크롤 깊이 4.7천·케이스 열기 3.4천·일반 클릭 2천·다운로드 2천)이었다. 이벤트에 붙은 값(path·seconds·metric·value 등)까지 하나씩 세면 약 10만으로 한도와 맞는다. 한도는 이벤트 값도 세는 것으로 본다.
- 정산에 쓰지 않거나 Umami가 이미 재는 값을 뺐다.
  - 페이지별 체류 시간: Umami가 방문의 머문 시간을 따로 잰다(일일 정산의 평균 체류도 그 값).
  - 웹 바이탈: 성능은 배포 전 측정으로 충분하다.
  - 스크롤 깊이, 이름 없는 일반 클릭(`click`, 누른 글자·바깥 링크 주소 포함).
- 남은 이벤트는 케이스 열기·다운로드·업데이트 내역·릴리즈 노트·제보 결과다. 같은 방문량에서 사용량이 약 80% 줄어 월 2만 안팎으로 본다.
