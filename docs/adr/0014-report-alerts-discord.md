# 0014. 제보 알림은 디스코드 웹훅으로 보내고, 못 보낸 것은 KV에 쌓아 Cron이 다시 보낸다

- 상태: 채택(0005 "알림은 카카오톡 하나로"를 대체)
- 날짜: 2026-10-06

## 맥락

- 0005는 "검토 대기 제보를 카카오톡에서 승인·거절"하는 흐름이었고, 알림 기록·토큰을 DB에 두려 했다.
- 그 뒤 결정이 바뀌었다.
  - 제보는 검토 없이 바로 이슈로 공개한다(0010) → 승인·거절할 것이 없다.
  - DB는 보류했다(0012) → 작은 상태값은 KV에 둔다.
- 이슈를 운영자 토큰으로 만들기 때문에 GitHub는 "내가 만든 이슈"로 보고 알림을 보내지 않는다. 새 제보를 알 방법이 따로 필요하다.
- 처음엔 카카오톡 "나에게 보내기"로 만들었다(OAuth 연결·KV 토큰·Cron 갱신까지 로컬 시험 완료). 그런데 **"나와의 채팅"은 폰 푸시 알림이 뜨지 않는다**(카카오 공식 FAQ). 앱을 열어야만 보이면 알림의 목적을 못 이룬다.

## 결정

- 새 제보 이슈가 만들어지면 **디스코드 웹훅**으로 운영자 채널에 보낸다.
  - 본문(푸시에 뜨는 한 줄): `새 제보 · 게임`
  - 임베드: 이슈 제목(누르면 이슈로), 제보 글 앞 300자, 사이트 강조색 띠
  - `allowed_mentions: { parse: [] }`로 사용자 글 속 `@everyone` 등이 울리지 않게 한다.
- 알림은 응답 뒤에 보낸다(`waitUntil`). **실패해도 제보는 성공**이고, 못 보낸 알림은 KV(`notify:pending`, 최근 20건)에 쌓는다.
- **Workers Cron(매시 정각)**이 쌓인 알림을 순서대로 다시 보낸다.
- 웹훅 주소(DISCORD_WEBHOOK_URL)는 비밀값으로 다룬다(주소만 알면 그 채널에 글을 쓸 수 있다).
- 개발(REPORT_DRY_RUN=1)에서도 알림은 실제로 보낸다(받는 곳이 운영자 채널뿐). 앞에 `[시험]`, 띠는 회색.

## 검토한 대안

- **카카오톡 "나에게 보내기"**: 만들어 보았으나 푸시가 뜨지 않는다. 토큰 갱신(접근 6시간·리프레시 2개월)도 관리해야 했다.
- **카카오톡 "친구에게 보내기"**: 푸시는 오지만 보내는 카카오 계정이 하나 더 필요하고(전화번호), 친구 목록 권한 신청·비즈 앱 전환이 필요하다.
- **알림톡**: 유료·사업자 등록 필요.
- **텔레그램 봇**: 비슷하게 간단하지만 운영자가 디스코드를 쓴다.

## 결과

- 로그인·토큰 갱신이 없어 비밀값 하나로 끝난다. Cron은 재전송만 한다.
- 폰 디스코드 앱의 채널 알림 설정을 "모든 메시지"로 두어야 푸시가 온다.
- KV 쓰기는 실패했을 때만 생긴다(무료 한도와 무관).
