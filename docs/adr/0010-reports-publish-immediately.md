# 0010. 사이트 제보는 검토 대기 없이 바로 이슈로 공개한다

- 상태: 채택(0004의 "검토 대기" 부분을 대체)
- 날짜: 2026-10-06

## 맥락

- 0004는 AI 판별(6단계) 전까지 모든 사이트 제보를 검토 대기로 받고, 카카오톡 승인 링크(0005)로 올리기로 했다.
- 제보는 각 패치의 **공개 저장소**에 이슈로 만들어진다. 공개 저장소의 이슈는 GitHub에서 바로 보인다.
- 검토 대기를 하려면 대기 중 제보를 둘 곳(DB 또는 비공개 저장소)과 승인 수단(카카오톡 링크 또는 관리자 화면)이 먼저 있어야 한다. GitHub는 비공개 저장소의 이슈를 공개 저장소로 옮기는 것도 막는다.

## 결정

- 사이트 제보는 **검토 없이 바로** 해당 패치 저장소에 `제보` 라벨 이슈로 만든다.
- 사이트의 제보 목록도 **바로** 보여 준다(GitHub 검색 API, 5분 캐시).
- 스팸·잘못된 제보는 운영자가 GitHub에서 **"Close as not planned"(또는 중복)로 닫는다.** 사이트 목록은 이렇게 닫힌 이슈를 빼고, 정상으로 닫힌(completed) 이슈는 "반영됨"으로 보여 준다.
- 거르기는 서버에서 차례로: CORS → 허니팟·작성 시간 → Turnstile → 요청 제한(KV, IP별 시간당 3건·사이트 하루 50건, IP는 해시로만) → 입력 검사 → 같은 내용 하루 1번. `@아이디`·`#번호`는 폭 없는 공백으로 무력화한다.

## 검토한 대안

- **사이트 목록만 승인제(라벨 `공개`가 붙은 것만 표시)**: GitHub 이슈는 어차피 바로 공개되므로 사이트만 막는 의미가 적다.
- **비공개 "제보함" 저장소 + 승인하면 Actions로 공개 저장소에 복사**: GitHub에 승인 전 내용이 안 보이지만, 저장소·워크플로가 하나 더 생긴다.
- **사이트 DB에 대기 + 관리자 화면**: 관리자 로그인이 필요해 0004의 "회원 기능 없음"과 맞지 않는다.

## 결과

- 바로 동작하고 관리할 것이 적다(승인 단계가 없다).
- 방어선을 뚫은 스팸은 닫기 전까지 공개된다. 닫으면 사이트 목록에서는 사라진다.
- 운영자 토큰으로 만든 이슈라 GitHub 알림이 오지 않는다. 제보가 왔는지 알 방법(0005 카카오톡 알림 등)이 아직 없다 → 따로 해결해야 한다.
- 6단계(AI 판별)를 붙이면 "의심되는 것만 검토 대기"를 다시 검토한다.
